# 资源规则

[`resource_rules.cfg`](../../addons/sourcemod/configs/resource_rules.cfg) 统一管理 AstRedux 的物资替换、区域例外和数量／分布，包括单图物资特例。Zone 系列继续使用框架资源设置与 Stripper。

## 入口与生效

规则文件须在地图生成前选定，修改配置或重载插件后换图生效。字段、单位和当前数值见配置文件注释。

`resource_rules_visualize` 可辅助检查分布：1 预览数量／分布裁剪，2 执行并高亮保留点。预览并非完全不改物资，替换仍照常执行。

## 结构与覆盖

配置按 `global` → `finale_defaults` → `maps/<地图名>` 逐层覆盖。未填写的字段继承前一级，分类的 `members` 列表整体替换。救援层与单图层使用相同字段，让救援补给可以统一调整，不必为每张三方图复制规则。

例如单图只改止痛药的固定上限并关闭密度，仍会继承全局的最小间距；省略字段不表示关闭该限制。MapInfo 提供区域信息，资源规则负责替换与限额。

单资源策略优先于分类：资源一旦有单独策略，整个资源就退出分类，包括该策略统计范围外的点。`limit -1` 只取消固定上限，不会交回分类，也不会关闭密度限制。要交回分类，须移除单资源策略；地图层省略字段不能取消继承。其余资源只能归入一个分类，不能靠声明顺序解决冲突。

## 数量与分布

数量按替换后的最终资源统计，按地面实体／刷新点计数，而不是可拾取次数。路线密度按有效路线区间的导航 flow 长度计算预算并向下取整；与固定上限同时启用时取较小值，间距或候选不足只会减少保留量，不会额外补刷。

有预算时沿有效路线区间分布选点，无预算时按间距筛选。整图 flow 无效或全部候选缺少 flow 时，跳过密度与路线区间筛选并告警，保留固定上限和间距约束；部分候选缺少 flow 时，优先有效点，再用无 flow 点填补同一预算。

## 区域与救援例外

区域识别优先使用 MapInfo，数据缺失时用精确盒子后备，起点识别优先。未知位置使用通用替换规则，按 `unknown` 参与数量限制。

`regions/finale` 不是整张救援图的替换规则：它作用于已识别的 `end` 区域及自动识别的救援补给。某种资源未在 `finale` 中指定时，依次查找 `end` 和通用 `rules`；其余位置仍按对应区域处理。

原本位于 `end` 的资源替换后仍属该区域，是否计入限额取决于策略的统计区域；默认的 `along,unknown` 不包含它。`flow_finale` 则只控制救援关的路线区间与密度筛选，不控制上述替换例外，也不关闭固定限额和间距。

### 救援补给自动识别

许多三方图没有预先录入救援区域。开启 `finale_supplies` 后，插件把救援关起点外紧凑摆放的四个及以上医疗包识别为补给，也识别起点外医疗柜中的物资。它们使用救援替换规则，并跳过数量和分布限制。

该识别不保证准确圈定救援场地：沿途符合条件的包组也会保留，零散或不足四包的补给可能漏掉。这是在兼容未经专门配置的地图与准确识别之间接受的取舍，必要时用单图规则补充。

识别需要先知道起点位置，以免把起点包当成救援补给。区域数据缺失时使用开局生还者位置；两者都未就绪时先保留物资，等生还者生成或队伍变化后重试，避免首轮误删。

### 医疗柜

医疗柜内物资在每轮初始化时由引擎生成，开门只是让玩家能够取用。因此插件按生成来源识别柜内物品，再应用 `health_cabinet_limit`，原有开门交互不变。

柜内数量不再由全局 Stripper 缩减，而由资源规则统一管理，使救援默认值和单图覆盖都能生效。起点外的救援柜补给不受沿途药品限额影响。医疗柜来源识别依赖 Linux 服务端接口。

## 地图物资与玩家物品

资源规则处理地图已有候选，不补刷被删除后留下的空缺。物品进入玩家装备后，即使传递或掉落，也退出地图替换、分布筛选和地面额度统计。

标准灌油任务资源按真实生成关联保护，不因地图含有灌油机关就放行全部普通油桶，也不按皮肤判断；兼容投票放行的资源同样豁免。灌油关联识别依赖 Linux 服务端接口。

同轮保留点固定，后续生成只能填补空位，重开重新选择。AstRedux 关闭 ItemTracking 的跨轮物资复用，由资源规则负责每轮布局；开启复用后与资源规则联用仍有保存失败问题，尚未通过运行验证。Zone 系列继续使用 ItemTracking 原有的 MapInfo 配置、数量／路线筛选和人数限额。
