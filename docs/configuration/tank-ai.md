# Tank AI：追击、越障与攻击取舍

Tank 增强优先补足追击、地形通过和近处攻击机会，保留玩家绕克、关门争取时间和贴身周旋的空间。连跳、越障和攻击并非越积极越好：插件抢走原生路线，可能让 Tank 反复爬高；路径保护过宽，又会打断正常连跳。

主要实现为 [ai_tank](../../addons/sourcemod/scripting/optional/coop/ai_tank.sp)，人数开关和参数见 [profiles](../../addons/sourcemod/configs/astredux_profiles.cfg)。连跳、投石、越障、拍门和翻越加速分别控制，关闭某个人数档的连跳不代表关闭其他移动能力。

## 连跳与原生路线

早期接近目标时会同时强加前进、跳跃和出拳，投石准备中也反复重新瞄准。后来的调整减少了这些干预：远处用连跳接近，近身交回原生近战；投石在出手时计算低抛角和目标移动提前量，释放后沿既定弹道飞行。

连跳停止距离曾参考最近的生还者，后来改为实际追击目标，避免附近的非目标干扰追击。为了允许更近的连跳接战，又加入近身和掉头减速，减少累积动量造成的冲过头；停跳采用接近时暂停、拉远后恢复，减少临界距离反复启停。

目标隔墙或跨层时，直线追人方向不一定可行，因此加速改为跟随原生移动意图。下降路线让位于原生，同高度缺口则保留跳跃机会。长距离路线继续由原生导航决定，插件通过 `anne_nextbot` 读取路径，协调眼前的移动。

引入路径预判后，1.5.0 曾因瞬时方向不一致、附近有梯子或跳跃自身高度而过度禁跳。后续修正将特殊路段保护放在地面判断，并区分跳高与路线实际落差，避免飞行途中取消已有跳跃。这减少了部分提前刹车保护，换回正常连跳的连续性。相关修正见提交 `6de0edcb`，实现见[路径判断](../../addons/sourcemod/scripting/optional/coop/ai_tank/path.sp)。

## 越障：从主动取近路到停滞后尝试

最初增加跳上低障碍、在顶面短暂追击，是为了减少桌椅和护栏处反复翻越、绕行。候选按物理空间检查，顶面没有连续 NAV 也可以尝试，以补足一小段原生路线缺口。

早期主要解决了“能跳上去且更接近目标”，没有充分考虑随后如何离开顶面。扩展侧向候选和多级台面后，可利用的追击机会增加，也放大了插件爬高与原生绕路之间的冲突。

因此在 `4e1f7eea` 中收紧为确认局部停滞后才尝试，并检查落点后是否有可走出口，失败位置暂缓重试。代价是失去部分主动取近路的能力：原生仍在绕行时，即使旁边存在可跳台面，也可能不进入越障流程。出口检查只覆盖眼前一段，后续仍可能需要绕下平台。

局部后退、短跳与长时脱困分层处理。局部尝试有次数限制，搜索失败也计入尝试，避免小幅挪动不断推迟最终救援；正在越障或脱困时先完成当前控制，再交还其他模块。实现见[移动与越障](../../addons/sourcemod/scripting/optional/coop/ai_tank/movement.sp)。

## 近处攻击机会

近处选人用于弥补忽视身边目标的弱点：有明显更近、可见且身体路线可达的生还者时，允许转攻并短暂保持，减少来回换人。旧目标与候选采用相同的可达判断，避免隔墙的旧目标凭直线距离压过真正能接近的人；长距离和跨层选路仍交给原生。

骑头处理参考 Anne。目标确实处于头顶拳击范围时，先正常挥拳，空拳后再补引擎向上扫拳检查，沿用正常伤害与范围。顺路打铁则利用当前追击方向上的攻击机会，不为找铁器离开路线。实现见[近处选人与骑头](../../addons/sourcemod/scripting/optional/coop/ai_tank/combat.sp)。

门后迟迟不挥拳的反馈促成了主动拍门，也使 AstRedux 停用了 `tankdoorfix`。旧插件在挥拳后补门伤害，新处理主动请求挥拳，两者解决的是不同环节；改用主动拍门后，不再保留旧插件额外补伤害的效果。锁门、安全屋门和不可破坏门仍遵守地图规则。

拍门和顺路打铁优先于额外加跳、局部脱困，等待正常挥拳冷却也不算卡死。出拳与投石仍受 `l4d2_tank_attack_control` 影响，实际攻击机会由这些处理共同决定。

## 长时脱困

[si_unstuck](../../addons/sourcemod/scripting/optional/si_unstuck.sp) 先尝试恢复原生寻路，仍无法解决时移动现有 Tank，保留血量等实体状态。普通特感要求原位置也隐藏，Tank 则允许从玩家可见的卡位中救出；目的地仍须隐藏、可通行并远离生还者，以减少卡死拖延，同时保留重新接敌的时间。

Tank 脱困优先利用队伍已经走过的路线，减少前方机关或障碍再次挡住 Tank 的机会。从本轮最近经过的位置开始向前回查，以 NAV flow 筛选全队后方的落点，并限制传送距离和寻路长度，避免送回过远路段。没有合适落点时继续重试。生还者能通过的路线未必适合 Tank；单向落差、后续关门或不准确的 flow 仍可能影响脱困效果。

早期只检查近期有移动尝试的 Tank，遗漏了有目标却没有输入的罚站，后来将其纳入观察。暂停不计入卡死时间，攻击、翻越及局部脱困留出完成动作的机会。攻击是否正在执行看实际动作，而非仅看可能被其他插件取消的攻击请求。

## 现有限制

局部越障缓解了部分护栏追击问题，但仍有空调外机附近绕圈、大角度转向迟缓和间歇停跳的反馈。大角度空中变向目前主要通过减速、落地后掉头处理，追击连续性仍有限。已有观察尚不足以区分具体场景中碰撞、原生输入和插件修正各自的影响。

顶面缺少 NAV 不能单独解释某处为何没有越障，因为物理越障本身不要求顶面 NAV；还需要区分是否进入停滞救援、候选是否可用及控制是否被其他移动判断接管。后续协同方向见 [ROADMAP](../ROADMAP.md)，发行记录见 [CHANGELOG](../CHANGELOG.md)。
