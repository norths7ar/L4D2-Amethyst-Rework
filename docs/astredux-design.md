# AstRedux 设计决策

本文按设计议题记录 AstRedux 已确定的玩法选择、理由与适用边界，供维护和后续调整时参考。具体参数和实际行为以当前配置与源码为准。

通用框架与插件职责见 [配置架构笔记](architecture.md)，版本变化见 [更新日志](CHANGELOG.md)，尚未落实的想法见 [开发计划](ROADMAP.md)。

## 准备与正式开局

加入准备功能是为了确保所有人都已经准备好开始。

准备阶段的倒计时行为也经历过修改：

1. 最开始沿用了 Competitive Rework 框架的 传送行为，但是它的选点逻辑有BUG，比如 Deathcraft2 M4，会导致生还者卡头、倒计时结束后仍然无法移动。
2. 第一次修改，改为【在每名生还者的当前位置freeze】，但是有些地图开局本来有可以用来玩的地方，玩家甚至可以跳出地图外。如果不重置位置，那这些生还者会在开局后直接死亡。
3. 目前的实现是改用了 `!return` 和 出门自动送回安全区的传送逻辑，预期应该安全无误，待实战验证。

## 人数适配与 AutoWipe 自动解控

沿用传统Ast系列的1-4人玩法，动态调整难度。此外实现了动态调整投票列表，单人的【按特感血量比例扣血 / 特感基础伤害】在多人时会变为 AutoWipe 相关调整开关。

关于 AutoWipe，默认代价是40实血，不足则扣倒地次数。之前只在2人模式打开，后面我在3-4人下也打开，主要是增加容错。

因为全被控是小概率事件，所以本插件此前也兼容了“有人倒地、挂边，也有人被控”的混合情况。但在克局比如3倒地的情况下，第4人被控也能触发判定，前3个人自动被拉起来并打死了Tank过关，这有点反直觉。

因此最终决定是，本插件只负责“全被控”情况，不再处理混合情况。目前考虑到了存在 AI Hunter 去扑已经倒地的尸体导致触发 AutoWipe 的情况，但是我选择接受，不单独写条件判断了。

## 技巧击杀播报、击杀回血、回子弹

插件层面，优化了 `l4d_stats` 和 `skill_detect` 之间分工不清晰、依赖反复查询配置开关的问题。改用了统一合并的 `skill_detect` 插件。

理论上新插件应该对之前的逻辑完全兼容、行为一致（除非我有过调整），如果有不同可以报BUG。现在空爆音效应该是对所有类型的空爆都在击杀者一侧触发。

击杀回血，现在设定是：基础回复2 ； 如果实血在20-39 回复量额外 +2，如果低于20 额外 +3 。关于星级操作对应的回复量，见下方表格。

但是星级奖励有两个例外，一个是协作空爆 Hunter 暂时没加。另外一个是 pop Boomer 暂时也没加。Pop的定义是 在不论复活多久后，干净的处理掉胖子（胖子没有喷、炸到生还）。迅速打爆胖子是 Shutdown，有奖励

Witch 使用独立的击杀回血规则，普通击杀 5、秒杀 8 与引秒 15 分档，且不受普通杀特回血开关或其他奖励机制影响。Tank 作为 Boss，暂不加入击杀回血、回弹或全队奖励。

击杀回子弹，由实际完成特感击杀的主武器获得对应类别的备弹，受备弹上限约束。但是平时基本不开，所以数值需要观察。

### 技巧奖励明细

| 击杀行为 | 奖励档位 | 额外实血 |
| --- | --- | --- |
| 普通特感击杀 | 无 | 0 |
| Hunter 协同空爆 | 无（播报一星） | 0 |
| Hunter 普通单人空爆 | 一星 | +1 |
| Hunter 空爆：近战、马格南爆头、狙击爆头、榴弹直击 | 二星 | +2 |
| Hunter 空爆：单喷一喷、微冲≤3发 | 二星 | +2 |
| 残血击倒冲锋 | 二星 | +2 |
| 满血击倒冲锋（目前做不到） | 三星 | +3 |
| 打死正在控制自己的 Smoker，完成自救 | 二星 | +2 |
| Jockey 空爆 | 二星 | +2 |
| Boomer 0.5 秒内干净击杀 | 三星 | +3 |
| Boomer 0.5 - 1.4 秒干净击杀 | 二星 | +2 |
| Boomer 1.4 - 2 秒干净击杀 | 一星 | +1 |
| Boomer 超过 2 秒（普通 Pop） | 无（播报一星） | 0 |

近战、马格南／狙击爆头及榴弹直击按最终击杀技巧优先分类，即使之前有队友补过伤害，也归入对应二星；单喷一喷、微冲三发及以内则要求没有其他玩家的伤害参与。

Boomer 的时间从出生算到死亡，不是从露头或第一次被打算起。上述 Shutdown／Pop 都要求没有喷中生还者，爆炸也没有溅到生还者；否则只按普通击杀处理。这里的 Pop 狭义分类指超过 2 秒的干净击杀，2 秒内归 Shutdown。

砍舌、秒救、打石头和触发警报本身不产生击杀回血；如果救人同时实际杀死特感，该次击杀仍按基础规则及其命中的技巧档位结算。

## 武器选择

以小枪为主，SMG和UZI继承了ZoneMod的定位，一个威力大一个打得准。MP5我想加入，但是暂时没想好如何定位。新的刷新插件会把所有步枪换成随机微冲。

单喷沿用了ZoneMod，相对比较水，我不希望武器太强。

狙击目前改用了Scout，伤害125、打坦克有乘区伤害150.

手枪、马格南、近战目前都沿用原版，近战强制限制只取1次（反例见Salthell M5 起点安全室）。电锯换成随机近战。

## 资源

### 补给与续航

医疗包统一替换为止痛药，包括起点、沿途、终点和救援区域，保持规则简单一致。针和电击器目前禁用，电击器的解禁留待后续讨论。

出门自动发药。起点原有的药也保留，为出门第一波失误、堵门或安全区过小造成的意外提供回头补给的机会。终点药沿用统一规则，没删，主要是考虑到实际使用机会较少，不想单独写规则判定了。

谁吃药、何时吃药、是否回头补给，也是药役的决策。额外发药会打乱这些选择，而高难地图已有击杀回血等续航选项，因此移除了商店和额外发药功能。多数主流地图的备弹压力较小，少数第三方地图的续航问题结合具体地图处理。

### 刷新与数量控制

随机补给点保留地图原始候选池，先由引擎抽取，再按规则删除或替换；抽到禁用品后留下空缺，不补抽。医疗包抽出后仍替换为止痛药，需要增加药量时可通过现有替换规则将针等物品也转为药。枪械 `weapon_selections` 的类别收窄独立保留。固定刷新点和运行时生成的资源继续适用删除与替换规则。替换保留原有刷新次数与地图交互，同一刷新点的武器类型保持一致；适用资源统一取消无限拾取，近战只取一次，弹药堆维持重复补弹。补给每轮重新随机，让重开也保留变化。

资源策略集中到插件配置文件，按字段采用“插件 global < 框架 mapinfo < 插件 maps/当前地图”的覆盖顺序。MapInfo 继续作为所有模式共用的基线，Redux 的地图特例写在插件配置中。默认仍无全局4药上限，已有章节限额保留；新增医疗、投掷物分类默认不限量。

限制针对替换后的最终资源，先执行单物品规则，再按首次声明顺序执行分类规则；只裁剪、不补抽。支持数量上限、路线进度区间及最小间距，按实体／刷新点计数，不按可拾取次数计数。默认统计沿途及位置未知资源，起终点豁免，可逐项调整范围；玩家随身物品不参与。路线筛选默认关闭，救援关默认豁免路线筛选但仍执行数量上限。武器、弹药堆及已识别的机关物品也能使用这些限制，兼容投票放行的资源豁免。配置结构、覆盖示例及新的 `resource_rules_*` 接口见[资源规则配置](configuration/resource-rules.md)。

区域规则可分别调整起点、终点和沿途的替换与清理。位置识别复用 `saferoom_detect`，以 `mapinfo` 优先、精确盒子后备，只有数据缺失时才切换来源；终点包括其中标定的救援区域。位置未知时应用通用规则，并参与数量限额统计。

### 机关资源与兼容投票

Redux 默认禁用投掷物，以及油桶、烟花、煤气罐和氧气瓶。为满足地图机关需求，`!ast` 提供三组兼容投票：榴弹、油桶与烟花、煤气罐与氧气瓶。同战役重开和换章节保留设置，换战役重置。

兼容投票只放行地图提供的资源，不额外补发。

## 地图

地图本身是难度的一部分，应保留地图自身的流程、机关和难度差异。长图与短图的补给需求不同，资源运营也是这种差异的一部分。

已有地图专属 Stripper 修改作为完整设计保留，包括随机补给改固定补给、终局修复和弹药堆布局。药箱最多2药的上限、药品密度修正也继续保留，后续结合实际问题逐项审视。

第三方地图可能依赖特殊实体或脚本机制，例如《伦理问题 Alpha 测试》需要榴弹触发机关。遇到兼容问题时，应连同地图脚本和 Stripper 一起检查：资源投票负责放行，已被 Stripper 删除的实体则需要在地图修改层处理。
